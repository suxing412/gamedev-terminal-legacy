## 一、现状（为什么是情报官先活）

1. **情报获取现状为零管道**：技术报道/工具/资讯/新形态/论文全靠制作人手动刷，无固定源、无固定时点、无沉淀——读没读过、读了什么、哪些值得回看，全无台账。
2. **英文源事实性弃读**：论文与一手技术报道多为英文，现状是「攒着不看」；定案已拍板「英文=AI 代读+中文精编+原文直达」，这是管道最大的增量价值点。
3. **可支配时间即将锐减**（本职工作变动），「每天 5 分钟读完一屏」的日报形态是唯一可持续形态——M1 的交付判据就是让每天先有这一屏。
4. **定案 M1 顺位明确**：情报官先活（源清单→抓取管道→双层呈现→骨架最小壳），方法论树（M2）、总监席（M3）、工作域（M4）均不在本令范围。

**M1 明确不做（无漂移清单）**：方法论树及三通道、Agent SDK 总监席、半屏/全屏可切换形态、Electron 常驻壳、监制台接入、dsh 调研。唯一预留：情报条目 id 可寻址（为 M2「一键沉淀」通道留数据接口，见 §3.2），只留形状不做功能。

## 二、目标形态

```
┌─ 定时调度 ──────────────────────────────────────────────────────────┐
│  抓取班次（时点待拍板）            日报装配（时点待拍板）              │
└──────┬──────────────────────────────────┬──────────────────────────┘
       ▼                                  ▼
  逐源适配器（RSS/页面两类）          候选集 → Opus high 精编 → 日报 md
       ▼                                  ▼
  去重 → 评分（权重规则）→ JSONL 台账落盘   digests/<日期>.md（正本，可脱离服务阅读）
       └──────────────┬───────────────────┘
                      ▼
              Web 服务（Node，服务与管道解绑）
        ┌─────────────┴─────────────┐
   原始流页（全源可翻）          精编日报页（5 分钟一屏）
   中文源：原文直达+重点标注     头条/SLG 垂直/主流广览/论文工具角
   英文源：中文精编+原文直达     尾注：源健康（抓取失败口径待拍板）
```

两条铁律贯穿：
- **管道与服务解绑**：情报管道是独立 CLI 可跑的纯 Node 模块（`node intel/run.js fetch|digest`），Web 服务只是它落盘产物的渲染器。服务挂了不丢抓取，管道挂了页面照常渲染既有日报。
- **正本在文件不在服务**：日报正本=md 文件、原始流正本=JSONL 台账，人用任意编辑器可读；Web 页面是视图不是存储（监制台「文件即正本」范式沿用）。

### 3.2 条目契约（JSONL 每行一条，落盘即冻结不回写）

| 字段 | 说明 |
|------|------|
| `id` | = dedupe_key = sha1(规范化 URL：去 utm/锚点/尾斜杠)；**M2 沉淀通道按此寻址**（本期只保证可寻址） |
| `source` / `tier` | 源 id + 源档位快照（S/A/B，见 §3.3） |
| `url` / `title` / `lang` | 原文直达链接 / 标题 / `zh`\|`en` |
| `published_at` / `fetched_at` | 源发布时刻 / 抓取落盘时刻（ISO 8601） |
| `raw_excerpt` | 源侧摘要或正文首段（原文语种，限长） |
| `zh_digest` | 英文源专用：中文精编段（抓取时为空，精编后**以补录事件行追加**，不改原行——台账 append-only 纯粹性） |
| `zh_highlights` | 中文源专用：AI 重点标注（句级定位），**绝不做摘要替代**（定案 Q2 原话纪律） |
| `tags` / `score` | 命中的权重关键词 / 评分快照 `{总分, 源基础分, 关键词分, 新鲜度分}`——分数构成落盘，日报可解释「为什么选它」 |

入报与否**不回写条目**，由 `digests\<日期>.json` 入选清单单独记账——原始流页渲染时联查标注。

### 3.3 情报官管道

| # | 环节 | 规格 | 期 |
|---|------|------|----|
| P1 | 源清单 | 正本=本目录《情报源清单》文档（**另一 agent 在拟，落稿后以其为准**，制作人过目后落成 `config/sources.json`）；每源字段：id/名称/类型(rss\|page)/语种/档位(S=SLG垂直\|A=主流必读\|B=广覆盖)/抓取地址/是否走代理 | M1a 单源起步，M1b 全量 |
| P2 | 调度 | 服务内建调度器（每分钟 tick 对时刻表，时钟可注入）；抓取班次+日报装配时点**待拍板①**（建议值见 §7）；服务重启后本班次未跑的任务补跑一次（游标判断，不重复） | M1b |
| P3 | 抓取 | Node 内置 fetch(undici)+ProxyAgent；条件请求（etag/last-modified 进游标）；单源超时 30s、班次内失败退避重试 2 次；**单源失败不阻塞全班次**，失败落 `health/fetch.jsonl` | M1a |
| P4 | 适配器 | 两类：RSS/Atom 通用适配器（一个模块吃所有 RSS 源）+ 页面适配器（逐源手写提取函数，输出统一条目形状）；M1a 只做 RSS 通用适配器，页面适配器随 M1b 全源接入补齐 | M1a/M1b |
| P5 | 去重 | 规范化 URL 哈希；跨源跨日去重（seen 台账载入当月+上月）；同 URL 二次出现静默丢弃并计入 health 统计 | M1a |
| P6 | 评分 | **权重全在 `config/scoring.json`，引擎是纯函数**：`总分 = 源基础分(按档位 S>A>B) + 关键词分(SLG/4X/strategy/经济系统…命中表) + 新鲜度分(按发布距今衰减)`。入报候选规则落成可执行两条：**S 档条目降门槛全入候选**（SLG 垂直深挖）、**A/B 档按总分取 top-N**（主流广覆盖，N 进配置）——「垂直深+主流广」从口号变成两行可测规则 | M1a |
| P7 | 代读精编 | **Claude 额度、模型档 Opus high（定案 Q10 已拍板）**；通道=claude CLI 无头调用（M1 不引 Agent SDK，理由见 §4；通道选择待拍板⑥追认）。已知坑全预置：代理 env 注入、中文走 stdin 不走 argv、从 Node spawn 直调避开 PS5.1 数组坑。**只精编入报候选中的英文条目**（不全量代读，额度可控）；精编产物以补录行落台账+装配进日报 | M1b |
| P8 | 日报装配 | 纯函数：候选集+精编产物 → `digests\<日期>.md` + 入选清单 json。版式定死一组（内部工具不做配置）：**头条 ≤3 → SLG 垂直区 → 主流广览区 → 论文与工具角 → 尾注源健康**；每条必带原文直达链接；英文条带精编段、中文条带重点标注；全文以 5 分钟读完为限（条数上限进配置）。**AI 通道失败降级**：出「本条未精编」标注的日报，绝不出空报、绝不静默吞报 | M1b |

## 四、技术选型与理由（监制台教训对账）

| 决策 | 选择 | 理由 | 对账的监制台教训 |
|------|------|------|------|
| 服务框架 | **零框架**：`node:http`+自写薄路由 | 需求面窄（JSON 读口×3+SSR 页×2），Express/Fastify 中间件生态用不上；零依赖=零升级税；同路线监制台已验证可行 | 服务与 UI 解绑（本次管道更进一步与服务也解绑） |
| UI | **无前端框架**，SSR+原生 JS 渐进增强 | 两页皆阅读型无复杂状态；新渲染引擎无历史包袱——明确不引入 morph/全页 diff 范式 | morph 全页 diff 长期税（甘特重做被迫开「岛」绕行） |
| 代码组织 | 多文件模块化起步，入口只装配 | 从第一行就分模块，不等膨胀再拆 | app.js 三千行级巨石，重做成本高 |
| 数据形态 | JSONL append-only 台账 + md 正本，**不做目录状态机** | 条目单向生命周期，无流转实体；文件即正本、服务只是视图 | 「目录即状态机+JSONL 事件流」范式按需自裁，不照抄 |
| 轻依赖 | 仅两个候选：`fast-xml-parser`（RSS/Atom 解析）、`marked`（md→HTML），皆 MIT/零传递依赖 | RSS 变体多、md 边角多，自写解析器是无谓成本；**依赖白名单待拍板⑤**，不放行则自写受限子集 | 依赖极简纪律沿用 |
| AI 通道 | claude CLI 无头（非 Agent SDK） | 无头坑已趟平（代理/stdin/放行工具三坑在案）；Agent SDK 是 M3 总监席的正统路，M1 管道用它是杀鸡用牛刀且引入嵌入复杂度 | codex/claude 无头调用坑均已入库复用 |
| 壳 | M1 不装 Electron，浏览器访问 | 常驻可切换形态是 M3 命题；但 A5 布局纪律先立 | Electron 镜像/打包路径/Chromium 124 flex 三坑届时按录处置 |

## 六、判据概要（H104：验行为+自证能红，grep 源码不算判据）

判据基座：`test\fixtures\` 立一套**合成源**（本地起 mock http 服务供适配器抓取：含正常 RSS、坏 XML、重复 URL、无日期条目、中英混合条目集）+ 一套**录制样本**（真实源快照+精编产物样本，AI 段判据不打真实额度）。

| # | 判据 | 红绿口径 | 自证能红 |
|---|------|---------|---------|
| C1 | 抓取落盘形状 | 合成源→`fetch`→断言 JSONL 行数与 §3.2 全字段形状、时刻为 ISO 8601 | 抽掉适配器字段映射一格→必红 |
| C2 | 去重 | 同合成源抓两轮→断言台账不增行、health 记重复计数 | 改坏 URL 规范化（保留 utm）→必红 |
| C3 | 评分与入选 | 合成条目集（S 垂直/A 主流/噪音三类）→断言入选集合与排序完全等于预期；**调 scoring.json 权重→断言入选集合随之变化** | 权重调整后集合不变→必红（规则没接配置） |
| C4 | 日报装配 | 录制候选集→`digest`→断言 md 五区齐全、头条数≤3、每条含原文链接、英文条含精编段、中文条含标注不含摘要 | 抽掉装配器某区→必红 |
| C5 | 降级路径 | 精编 stub 注入失败→断言日报仍产出且带「未精编」标注、进程零退出码、health 记 AI 失败 | 把降级改成抛异常→必红 |
| C6 | 单源故障隔离 | 合成源一坏一好→断言好源条目照常落盘、坏源入 health、班次整体成功 | 去掉逐源 try 隔离→必红 |
| C7 | 调度 | 注入模拟时钟走完一天→断言抓取班次/装配各触发一次、重启后补跑恰一次不重跑 | 时钟拨过时点两次→触发两次则必红 |
| C8 | 页面渲染 | 起服务→GET 日报页/原始流页→断言 200+五区结构+「已入报」徽章联查正确 | 删入选清单 json→徽章断言必红 |
| C9 | 空态 | 无当日报→GET `/`→断言空态文案+最近一期入口，非 404 非白屏 | 去掉空态分支→必红 |
