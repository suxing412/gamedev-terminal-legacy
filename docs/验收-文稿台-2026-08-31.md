## 一、被交付的东西

终端（本机 127.0.0.1:4280 的一块常驻值班屏，**开机自启、整天开着、无鉴权**）多了第七个页签「文稿」：

- **文件库**：五个根、948 份 md，树 + 文件名过滤 + 正文搜索
- **阅读态**：服务端渲染，左侧记号栏列出 `【改】【加】【删】【问】` 的位置，点了跳过去
- **编辑态**：CodeMirror 6，左源码右预览，预览每段旁边四个一键记号钮
- **文件锁**：租约 45 秒 + 闲置 30 分钟降级，状态落盘
- **版本环**：每次写入一版，带「谁写的」，上限 50
- **冲突**：三路（盘上 / 我的 / 打开时那版的字节）

**这是终端的第一个写口。**在它之前，终端对外纯只读——五个 POST 口没有一条把请求体落盘。

## 二、关键实现（请逐条攻）

### 2.1 写口的四道闸

```
① Content-Type 必须 application/json（text/plain 一律 415）
② Origin 必须在自家白名单（缺 Origin 也拒）
③ 一次性写令牌（随页面 HTML 下发，12 小时过期，台内上限 200）
④ 路径校验 + 写权分级
```

设计意图：`text/plain` 是"简单请求"不触发 CORS 预检，跨站脚本能直接发出去
（`mode:'no-cors'`，响应读不到但**写会发生**）。要求 JSON 就必须过预检，而我们不给 CORS 头。

### 2.2 路径校验（`server/lib/文稿.js` 的 `校路径`）

```
① 根键必须在根表里
② 形状：非空、≤400 字符、非绝对路径、无 NUL、逐段判 `..`、必须 .md、无 Windows 非法字符
③ realpath：**取父目录的 realpath 再拼文件名**，判断落点在根内（大小写不敏感）
④ 存在性（须存在时 statSync().isFile()）
```

为什么取父目录：新建文件时 `realpathSync(文件)` 直接 throw，照抄旧的 `校档名()` 会让新建路天然失效。

### 2.3 写权分级

| 根 | 份数 | 写 |
|---|---:|:---:|
| 终端仓 / Ticketflow / TK | 316 | 可写 |
| 工作室 · 静态区 | 135 | 可写 |
| 工作室 · **活存储**（回执/完成/归档/journal/项管台账/终端班次） | 427 | **禁写** |
| 记忆库 | 70 | 只读 |

活存储禁写的理由（来自 `studio.config.json` 注册表原文）：
*「runner 每拍读写它们，并发写产生的状态错乱 git 也还原不回。」*

### 2.4 文件锁（`server/lib/文锁.js`）

```
判态(条, 现在) → 无 / 持有 / 可抢 / 过期
  过期  ：现在 - 末续 > 45 秒        （管崩溃、换装杀进程、关页面）
  可抢  ：现在 - 末键 ≥ 30 分钟      （管「人走了但页面还开着」）
  持有  ：其余
```

- 锁**落盘**在 `<终端根>/文稿/锁.json`（原子写：tmp + rename）
- `外部可写(绝对路, 根表)` 供**另一个进程**（坐席子进程、PreToolUse hook）查询
- 页面每 15 秒续租；`有按键` 为真才推 `末键`
- 别人想改被锁文件 → `请求解锁()` 记一条 → 进人闸队列（带等待时长，起点不刷新）
- 坐席的 prompt 前面加占用告示（`/api/say` 与班次两条路都加）

### 2.5 冲突三路

存盘时比对「打开时的指纹」与「盘上当前的指纹」，不同即 409，返回：

```
{ 冲突: true, 盘上: <全文>, 我的: <全文>, 基文: <打开时那版的字节>, 能三路: bool }
```

**base 的字节落盘**（`文稿/草/<键>.base.md`），不是只存哈希——三路合并要的是字节。
存盘成功后 base **重置成刚存的那一版**（不是删掉）；重新取锁时 base 重设为盘上当前
（除非手上还压着一份没存完的草稿，那份 base 属于那份草稿）。

### 2.6 草稿

每 800ms 落**服务端**，不落 localStorage。
理由：4280 被占时 `start()` 会顺延到 4281，origin 一变 localStorage 就找不着了——
而那正是「进程刚被杀过、最需要草稿」的场景。

### 2.7 三条防丢

| 丢法 | 拦法 |
|---|---|
| 切页签（`视图.js` 的 `innerHTML` 会连内容一起删，成本一次点击） | `视图将换` 可取消事件 + confirm |
| Ctrl+R（`main.js` 绑成无确认重载） | `beforeunload`（**只是尽力**）+ 服务端草稿兜底 |
| 换装 / 崩溃 | 服务端草稿 |

### 2.8 片段脚本

页面的 `<script>` 在 `</main>` 之外，而片段中间件只抠 `<main>`，`innerHTML` 又不执行 script
——**原始流 / 监视 / 席间存照 / 文稿 四页的前端脚本在主页壳里从来没跑过**。
修法：片段带 `data-脚本`，`视图.js` 按需加载（每个只加载一次，防定时器叠罗汉），
装好后广播 `视图装好`，各页脚本改成可重入的 `装()`。

**242 项全绿；自证能红 70 处变异全部翻红。**（今天开工时是 161 项 / 31 处。）

新增判据文件：`md渲染`(22) `文稿`(24) `文锁`(23) `写闸`(9) `写口`(18) `构建`(4)。

**明写的盲区**：记号栏的 DOM 渲染没有判据——无头 Electron 窗口 `visibilityState` 恒为 hidden，
Chromium 完全不派发 `requestAnimationFrame`、把 `setTimeout` 节流到约 1Hz，

所以只验它的纯函数输入输出，DOM 那一跳明写为盲区，不假装覆盖。

## 四、请重点攻的六个方向

1. **写口**：四道闸有没有能绕过去的路？（提示：Electron 的 `file://`、本机其它服务的 SSRF、
   浏览器扩展、`fetch` 之外的发送方式、Origin 头的边缘取值）
2. **锁**：45 秒租约 + 30 分钟闲置这两个阈值，有没有能造成「两个人同时以为自己独占」的时序？
3. **冲突**：三路的 base 在什么情况下会是错的？重置 base 的几处时机有没有漏的路径？
4. **路径**：`校路径` 四道在 Windows 上有没有绕法？（ADS `:$DATA`、8.3 短名、UNC、保留设备名、
   尾随点与空格、Unicode 归一化）
5. **数据丢失**：除了已列的三条防丢，还有哪条路能让制作人的编辑无声消失？
6. **这东西三个月后是活的还是死的**——这块屏上「需要人到场的格子」历史死亡率是 100%，
   六个页签里五个已经凉了。文稿台凭什么不一样？如果它也会死，最早的死亡信号是什么、多久出现？
