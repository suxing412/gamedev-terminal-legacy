# 游戏开发者终端 · 需求定案

> 2026-08-25 制作人发起：「包含我作为一个游戏制作者的全部工作相关内容的终端——职业规划和路径、
> 技能成长、最新游戏技术报道/开发工具/资讯/游戏形态与尝试/论文。」
> 经 grilling 拷问会（三轮十一问）逐条拍板，本文档=全部决策的定案记录。
> **不着急做**——开工另等制作人发话，本文档先立此存照。

## 一、本体定位

**「制作人这个人」的常驻终端**——主体是人不是项目。三域全含：

| 域 | 内容 | 期次 |
|---|------|------|
| **情报雷达** | 技术报道/开发工具/资讯/新游戏形态/论文，双层呈现 | 首期 |
| **成长系统** | 职业规划路径+游戏设计方法论活 wiki | 首期 |
| **工作域** | 监制台接入（其时监制台降为常驻服务/插件，终端是 UI） | 后期 |

背景锚点：制作人梦想=垂直研发 PC 端 SLG；专业=游戏设计与开发（策划/程序/美术全涉猎不专精）；
自认实践派、理论是短板；2026-09-01 起本职工作变动，可支配时间锐减。

## 二、拍板全录

1. **三域全含，工作域后接**（Q1）：监制台工作域覆盖已全面，后期以常驻进程/插件形态接入，不重写。
2. **情报双层制**（Q2/Q7）：原始流（全源可翻）+精编日报。**筛选权重：SLG 垂直深挖+主流游戏广覆盖**
   （「在中国混游戏圈要多接触主流」）。**源越广越好、全类型都要**：技术报道/工具/资讯/新形态实验/论文。
   **英文源=AI 代读+中文精编+原文直达；中文源=原文必读，AI 只做重点标注、不做摘要替代。**
3. **成长系统=方法论树**（Q3/Q6）：一棵有体系的活 wiki（系统设计/经济循环/战斗数值/叙事/关卡/制作管理…，
   树骨架本身可重构）。**三通道接枝**：
   - **B 对话沉淀（主通道）**：制作人带实践困惑与总监席对话→AI 整理理论要点成条目草稿（区分制作人观点
     与引用成说）→制作人审后入树；
   - **C 情报转化**：日报好文一键「沉淀」→挂到方法论树对应分支，存 来源+要点+制作人按语；
   - **A 手写兜底**。
   自有观点与引用成说分色标注——数月后能看见「我的方法论」从引用堆里长出枝干。
4. **常驻可切换**（Q4/Q8）：一直挂在桌面；半屏情报塔 ⟷ 全屏工作台可切换，与 Unity/浏览器共存。
5. **骨架自建**（Q5）：新起 Web 服务（服务与 UI 解绑、新渲染引擎、模块化起步——监制台教训全吸收）；
   **AI 总监席用 Claude Agent SDK 嵌入**（Model+Harness=Agent，SDK 是「我坐进终端」的正统路）；
   **dsh（DeepSeek Harness，MIT，2026-08-13 v0.1）另开调研单**——插件架构偷师+执行器池候补，骨架不押它。
6. **wiki 各归各**（Q9）：方法论树跟人走一辈子，监制台 wiki（项目知识）随项目归档——生命周期不同即分立
   （H52 精神）。终端开窗可看监制台 wiki，不搬家。
7. **情报官=Claude 额度，模型档 Opus high**（Q10）：定时抓取→筛选→代读→精编，吃工作室现有额度池。
8. **命名：游戏开发者终端**（Q11）。

## 三、首期分期建议（待开工令后细化为施工令）

- **M1 情报官先活**：源清单落地（每类 1-2 个最高质量源起步，逐步扩）→定时抓取管道→双层呈现
  （原始流+精编日报）→骨架最小壳（Web 服务+日报页，先让每天有一屏可读）。
- **M2 方法论树**：树骨架初版（与制作人对谈定分类）→三通道（对话沉淀/情报转化/手写）→分色标注。
- **M3 总监席+可切换形态**：Agent SDK 嵌入对话席→半屏/全屏双形态→常驻。
- **M4 工作域接入**：监制台服务化改造+终端开窗。
- 随行：dsh 调研单（插件架构报告+能否接 Claude 模型层+执行器池可行性）。
