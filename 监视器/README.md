# 监视器

终端的监视子系统。**这个文件夹只管「显示什么、怎么判健康」，不管「什么算事件」。**

后者归瞭望塔的 `规则.json`（在部署区 `瞭望塔/` 下）。两份配置分家是故意的，
但人容易在错误的那份里找东西，所以先说清楚：

| 你想改的事 | 改哪份 |
|---|---|
| 某条流水该不该弹通知、算急还是常 | 瞭望塔的 `规则.json` |
| 终端上多一格 / 少一格 / 某格怎么判健康 | 本目录的 `监视器.json` |
| 加一路全新的信源（比如引擎、CI） | 瞭望塔 `watchtower.js`（要改代码） |

---

## 为什么监视归瞭望塔采集、终端只负责呈现

一句话：**采集必须比任何会话活得久，呈现可以随会话来去。**

2026-08-29 的实证：会话侧曾经挂过三个 Monitor 加四条 cron 做同样的事。
会话一关它们全没了；而 cron 那四条**从注册起就没触发过一次**（见 `监制台/坑档案.md`）。
同一时间瞭望塔作为独立进程连续在岗十二小时，五路信源一路没漏。

结论写进设计：**采集只留瞭望塔一处，终端不自己去 tail 任何东西。**
终端读的是瞭望塔已经落盘的三个文件，读不到就显示「读不到」——
不猜、不补零（PRODUCT.md 设计原则 5）。

## 加一格监视：不用改代码

往 `监视器.json` 的 `格[]` 里加一条即可。**只要用的是已有的型，一行 .js 都不用动。**

三个枚举各是一张注册表：

- **`源.型`** —— 数据从哪来：`行文件` / `jsonl` / `时刻文件` / `HTTP`
- **`健康.型`** —— 怎么算健康：`新鲜度` / `HTTP200` / `有新行` / `积压上限`
- **`呈现.型`** —— 长什么样：`灯` / `事件流` / `计数与清单`

**新增一种型才需要动代码；加一个格不需要。** 这条是本子系统可扩展性的全部含义，
也是验收标准第 1 条盯的东西——判据会造两份配置（4 格 / 5 格），断言页面渲染出的格数跟着变。

### 模板一：盯一个「该定期更新的文件」

```json
{
  "键": "引擎测试",
  "名": "引擎测试结果",
  "源": { "型": "时刻文件", "路径": "../../TK/enginectl-results.xml" },
  "健康": { "型": "新鲜度", "阈值毫秒": 86400000, "说": "超过一天没跑过就该提醒了" },
  "呈现": { "型": "灯" }
}
```

### 模板二：盯一个「该有人消费的队列」

```json
{
  "键": "信道",
  "名": "外厂来信",
  "源": { "型": "jsonl", "路径": "信道未读.jsonl" },
  "健康": { "型": "积压上限", "阈值": 5 },
  "呈现": { "型": "计数与清单" }
}
```

---

## 判健康的四型，各自在防什么

| 型 | 判什么 | 防的是 |
|---|---|---|
| `新鲜度` | 文件里的时刻距今多久 | **写的人死了**（瞭望塔心跳走这一型，阈值 90 秒 = 三个周期，与监制台 G20 同一把尺） |
| `HTTP200` | 端点通不通 | 服务起不来 |
| `有新行` | 一段时间内有没有新内容 | **流停了而进程还在**（比进程存活更严的判据） |
| `积压上限` | 未消费的条数 | 有人在等而没人处理 |

**没有第五型「进程在不在」是故意的**：进程在而不干活，是本仓反复栽过的形态
（cron 在册不触发、假换装 API 通着却是旧进程）。**判活性不判存在。**

---

## 读不到 ≠ 出事

某一格取不到数时，它的状态是**「读不到」**，不是「不健康」，也不是 0。

这三者在界面上必须长得不一样——把「不知道」显示成一个具体的数，
是这块屏能犯的最严重的错（PRODUCT.md：这块屏的全部可信度建立在「它说的就是产线的现状」上）。
